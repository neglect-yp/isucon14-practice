# #5-safe: SSE 切断時の未完了トランザクションを防ぐ

SSE 切断時のトランザクション開始を安全にする整合性修正。#5 の初回に椅子アクティベート 401 が 2 件あり、登録したトークンが DB の別接続から見つからなかった。

同じ登録用接続の記録は BEGIN（13:17:29.215）→ 終了処理なしで別要求に再利用 → 椅子 INSERT（29.230 / 29.240）→ 次の BEGIN（29.264）。別接続による認証 SELECT は、この間に 0 件を返した。値そのものや認証トークンはレポートに含めない。

使用中の SQLx 0.8.2 の MySQL 実装では、BEGIN の応答を await した後に transaction_depth を加算し、Transaction ガードを生成する。その await の途中で SSE の body が破棄されるとガードがなく、ROLLBACK を予約せず接続をプールへ返せる。

接続取得後、BEGIN の完了だけを独立した Tokio タスクで保護する。呼び出し元が消えても BEGIN を完了し、生成した Transaction ガードの破棄で ROLLBACK を予約してから接続を返す。接続取得の待機は外側に残し、切断済みの要求がプールの空きを待ち続けることを避ける。

統合テストは MySQL プロトコルの中継を使い、サーバーが BEGIN を実行した後、その OK をクライアントに渡す直前で停止する。この時点で呼び出し元をキャンセルし、同じプール接続で椅子を INSERT。別の DB 接続から見えることを検証する。修正前の `pool.begin()` に戻した対照は期待どおり FAIL（0 件）、修正後は PASS（1 件）。全 13 テスト PASS。

この修正は正しさのために採用する。比較元は直前の #5 の 2 回、修正後は続けて 2 回測定したもので、交互比較ではない。性能の増減をこの修正単独の因果効果とは主張しない。ベンチマーカー・SQL スキーマ・DB 耐久性設定は変更していない。
