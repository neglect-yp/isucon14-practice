# #5-initial: 近隣検索 N+1 解消の初期案

近隣の椅子検索では、全椅子を取得し、稼働椅子ごとに全ライド、各ライドの最新状態、現在座標を別々に取得していた。直前までの計測では、このライド・状態検索が数十万 SQL を占める。通信の往復を減らして近隣検索の応答と DB 接続の占有時間を短縮する仮説を検証する。

稼働中の椅子に最新座標を結合し、距離条件と未完了ライドの NOT EXISTS を一つの SELECT にする。「過去に一つでも未完了ライドがある椅子を除外」の条件を維持し、最新ライドだけを調べる簡略化は行わない。同じ時刻の場合は ID で順序を確定する。

統合テストでは、稼働・停止、距離の境界、古い座標と最新座標、古い未完了ライドと新しい完了ライドが共存するケースを確認する。SQL 回数だけでなく、新しい SQL の実行時間・走査量と API の平均 / p95、全体スコアを比較する。

全 12 テスト PASS。これは初期案の比較。近隣 API とスコアは改善したが、SQL 累積時間と走査量が増えたため、最終採用前に問い合わせを調整する。
