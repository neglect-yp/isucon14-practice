## 変更と根拠

変更は [1-schema.sql](../../../webapp/sql/1-schema.sql) の以下 2 本。ベンチマーカー、Rust アプリケーション、クエリ本文は変更していない。

```sql
INDEX idx_ride_statuses_ride_id_created_at (ride_id, created_at)
INDEX idx_chair_locations_chair_id_created_at (chair_id, created_at)
```

- 前回の slow log と EXPLAIN で、ride の状態検索と椅子の最新座標検索が全件走査・ソートを行うことを確認した。
- 追加前の実 DB では ride ごとの状態履歴が平均 5.7637 件、最大 6 件。まず `(ride_id, created_at)` で該当 ride に絞り、未通知判定も同じインデックスで処理する構成とした。
- スキーマに追加したため、ベンチマークの DB 初期化後も維持される。今回の初期化後に SHOW INDEX と EXPLAIN で確認した。
- 対象 5 種類の検索すべてで `type=ALL / key=NULL / Using filesort` から `type=ref / 追加インデックス利用 / filesort なし` に変化。最新状態・最新座標は逆方向のインデックス走査。
- [実行計画の確認 SQL](./explain.sql) と [計測後の実行計画](./explain.txt) を保存。
